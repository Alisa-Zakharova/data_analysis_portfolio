# Анализ вакансий «Аналитик данных» на основе открытого API портала «Работа России»

## Аннотация

Проект посвящён выгрузке, очистке и разведочному анализу данных о вакансиях,
размещённых на портале «Работа России» (TrudVsem). Основной объект
исследования - вакансии категории «Аналитик данных». Дополнительная задача
проекта - демонстрация полного аналитического пайплайна: получение данных
через API, приведение JSON к табличному виду, оценка качества данных,
фильтрация целевой выборки, расчёт описательных статистик и визуализация.

## Цель и задачи

Цель проекта - получить количественную характеристику рынка вакансий
аналитиков данных по данным открытого API и оценить качество исходных
данных.

Задачи:

1. Выполнить постраничную выгрузку вакансий через API TrudVsem.
2. Привести вложенную JSON-структуру к плоской таблице.
3. Оценить полноту и качество данных: пропуски, дубликаты, аномальные
   значения заработной платы.
4. Выделить целевую подвыборку вакансий аналитиков данных.
5. Рассчитать descriptive statistics по заработной плате и требованиям
   к опыту.
6. Провести частотный анализ навыков.
7. Сформулировать ограничения анализа и направления дальнейшей работы.

## Источник данных

- **API:** `https://opendata.trudvsem.ru/api/v1/vacancies`
- **Поисковый запрос:** `аналитик данных`
- **Период выгрузки:** определяется датой выполнения ноутбука.
- **Объём исходной выборки:** 6 страниц по 100 записей.
- **Объём после дедупликации:** 506 уникальных вакансий.
- **Идентификатор дедупликации:** поле `id`.
- **Формат данных:** JSON; вложенные структуры разворачиваются средствами
  `pandas.json_normalize`.
- **Количество признаков после разворачивания:** 58 столбцов.
- **Авторизация:** не требуется.

## Используемый стек

- Python 3;
- `requests` - взаимодействие с API;
- `pandas` - обработка, очистка и агрегация данных;
- `matplotlib` - визуализация;
- `collections.Counter` - частотный анализ навыков;
- Jupyter Notebook / Google Colab.

## Методология

1. **Выгрузка данных.** Запросы выполняются постранично с параметрами
   `text`, `limit` и `offset`. Полученные записи объединяются в единый
   список и дедуплицируются по полю `id`.
2. **Нормализация структуры.** Вложенные JSON-объекты преобразуются
   в плоскую таблицу с помощью `pandas.json_normalize`.
3. **Оценка качества данных.** Рассчитываются:
   - количество и доля пропусков по столбцам;
   - количество уникальных значений по ключевым признакам;
   - наличие дубликатов по `id`;
   - распределение значений заработной платы, включая нулевые значения.
4. **Формирование целевой выборки.** Отбор вакансий осуществляется
   по регулярному выражению `аналитик данных|аналитик больших данных`
   в поле `job-name`.
5. **Очистка заработной платы.** Поля `salary_min` и `salary_max`
   приводятся к числовому типу; значения `0` интерпретируются как
   отсутствие сведений и заменяются на `NaN`. Установлено, что все
   вакансии в выборке указаны в рублях.
6. **Разведочный анализ.** Выполняются:
   - сводка по регионам: количество вакансий, количество вакансий
     с указанной заработной платой, медианная нижняя граница;
   - частотный анализ навыков;
   - анализ распределения требуемого опыта;
   - построение boxplot для нижней границы заработной платы.

## Основные результаты

### Качество исходной выборки

В исходной выборке из 506 вакансий ключевые поля
(`job-name`, `salary_min`, `salary_max`, `region.name`,
`requirement.experience`, `creation-date`) заполнены полностью.
Наибольшая доля пропусков наблюдается в служебных и дополнительных полях:
`category.industry` - 505 пропусков, `scheduleTypeComment` - 501,
`benefitDetails` - 499, `medicalCertificate` - 495.

Дубликаты по полю `id` отсутствуют.

### Заработная плата

В 99 из 506 вакансий хотя бы одно из полей `salary_min` или `salary_max`
равно нулю, что фактически означает отсутствие указанной суммы.
Распределение вакансий по статусу заработной платы:

| Статус | Количество вакансий |
|---|---:|
| Указана сумма | 407 |
| Указана только заработная плата «от» | 69 |
| Заработная плата не указана | 30 |

Все значения заработной платы представлены в рублях; необходимость
конвертации валют отсутствует.

### Целевая подвыборка «Аналитик данных»

По регулярному выражению отобрано 25 вакансий.

Характеристики заработной платы:

- нижняя граница указана в 21 вакансии из 25;
- медианная нижняя граница - 92 000 руб.;
- минимальная нижняя граница - 40 000 руб.;
- максимальная нижняя граница - 220 000 руб.

Навыки указаны в 8 вакансиях из 25. Наиболее часто встречающиеся навыки:

| Навык | Частота |
|---|---:|
| Python | 6 |
| Pandas | 5 |
| SQL | 4 |
| LLM / Large language model | 3 |
| FastAPI | 2 |
| Machine Learning | 2 |

Распределение требований к опыту в целевой выборке смещено в сторону
значений 1 год, 3 года и 5 лет; присутствуют две вакансии без
требований к опыту.

## Визуализация

В ноутбуке представлены:

- boxplot распределения нижней границы заработной платы для вакансий
  аналитиков данных;
- таблица `region_summary` с агрегированными показателями по регионам;
- таблица `quality` с показателями полноты и вариативности ключевых
  признаков.

## Ограничения анализа

1. **Малый объём целевой подвыборки.** 25 вакансий аналитиков данных
   недостаточно для устойчивых статистических выводов; результаты
   носят преимущественно иллюстративный характер.
2. **Неполнота сведений о навыках.** Навыки указаны только в 8 из 25
   целевых вакансий, что ограничивает репрезентативность частотного
   анализа.
3. **Интерпретация заработной платы.** Показатель `salary_min`
   отражает нижнюю границу, а не фактическую заработную плату.
   Медиана по нижней границе является консервативной оценкой.
4. **Специфика источника.** Портал TrudVsem ориентирован в первую
   очередь на государственные и бюджетные организации; распределение
   заработных плат и требований может отличаться от данных hh.ru,
   Habr Career и иных коммерческих платформ.
5. **Ограниченный объём выгрузки.** Анализ выполнен по шести страницам
   выдачи и не претендует на исчерпывающее покрытие рынка.
