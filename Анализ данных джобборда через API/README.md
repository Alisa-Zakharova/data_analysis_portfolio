# Анализ вакансий аналитиков данных через API «Работа России»

Учебный проект по получению, очистке и разведочному анализу вакансий из открытого API портала «Работа России» (TrudVsem). Он демонстрирует небольшой аналитический цикл: загрузку JSON, нормализацию структуры, проверку качества и описание выбранной подвыборки вакансий.

## Цель и вопросы

- Какие сведения о зарплате и опыте указаны в полученной выборке?
- Какие навыки перечислены в вакансиях, отобранных по названию «аналитик данных»?
- Насколько полны исходные поля и насколько выборка ограничена способом выгрузки?

## Источник и охват

- API: [`https://opendata.trudvsem.ru/api/v1/vacancies`](https://opendata.trudvsem.ru/api/v1/vacancies)
- Поисковый запрос: `аналитик данных`
- Запросы в ноутбуке: 6 страниц по 100 записей с параметрами `text`, `limit` и `offset`.
- После объединения страниц и удаления повторов по `id` в сохранённом запуске осталось 506 уникальных записей.
- После фильтра по названию `аналитик данных|аналитик больших данных` осталось 25 вакансий.

API открытый, авторизация не требуется. Выгрузка выполняется при запуске ноутбука, поэтому при повторном запуске состав данных и результаты могут измениться. Репозиторий не содержит зафиксированный файл-снимок ответа и точную дату сохранённой выгрузки; приведённые ниже числа относятся к сохранённым результатам ноутбука, а не к текущему рынку вакансий.

## Метод

1. Получить записи API постранично и объединить ответы.
2. Удалить повторные вакансии по `id`.
3. Преобразовать вложенные JSON-поля в плоскую таблицу через `pandas.json_normalize`.
4. Посчитать пропуски, дубликаты и уникальные значения ключевых полей.
5. Привести `salary_min` и `salary_max` к числам; нулевые значения трактовать как отсутствие суммы.
6. Отобрать целевые вакансии по названию, изучить зарплатные границы, опыт, регионы и перечисленные навыки.

Стек: Python 3, `requests`, `pandas`, `matplotlib`, `collections.Counter`, Jupyter Notebook / Google Colab.

## Результаты сохранённого запуска

### Все 506 уникальных записей

Ключевые столбцы присутствуют в строках, но нули в зарплатных полях используются как код отсутствующей суммы. В 99 вакансиях хотя бы одно зарплатное поле равно нулю:

| Состояние зарплаты | Количество |
|---|---:|
| Указана сумма | 407 |
| Указана только нижняя граница | 69 |
| Сумма не указана | 30 |

Дубликатов по `id` в сохранённой выборке не найдено. В развёрнутой таблице было 58 столбцов; большая часть дополнительных полей почти всегда пустая.

### 25 вакансий целевой подвыборки

- Нижняя граница зарплаты указана в 21 вакансии; медиана этой границы - **92 000 руб.**, минимум - **40 000 руб.**, максимум - **220 000 руб.**
- Навыки перечислены в 8 из 25 вакансий. Среди указанных чаще встречались Python (6), pandas (5), SQL (4), LLM (3), FastAPI (2) и Machine Learning (2).
- Требования к опыту неоднородны; две вакансии не содержали требования к стажу.

Размер подвыборки и неполнота поля навыков слишком малы для широких выводов о рынке или сравнений профессий.

## Визуализация

В ноутбуке показаны распределение нижней границы зарплат и сводные таблицы качества и географии. Средние и медианы зарплаты относятся только к отфильтрованным объявлениям в этой выгрузке.

## Ограничения

- Выгружено только шесть страниц результатов; это не полная перепись вакансий.
- Поисковая выдача и данные API могут меняться между запусками.
- Целевая подвыборка содержит 25 объявлений, а навыки указаны лишь в восьми.
- `salary_min` - нижняя граница из объявления, а не фактическая зарплата.
- Частотность навыка отражает только заполненные объявления и не является оценкой доли рынка.
- Портал и способ поиска могут не охватывать коммерческие площадки и все названия должностей.
